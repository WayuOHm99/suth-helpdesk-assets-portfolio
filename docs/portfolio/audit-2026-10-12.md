## ช่องว่างที่เก็บเพิ่มแล้ว

รอบเก็บแรกมีประวัติ Git และรายการ PR ของผู้พัฒนา แต่ยังไม่มีบทสนทนาครบจาก GitHub จึงเพิ่มชุดเก็บส่วนตัวของต้นทางดังนี้:

- 183 Issues และ 159 PRs รวมทั้งเปิดและปิด
- 126 comments ของ Issues/PRs
- ตรวจรายการ review ของ PR ครบ 159 รายการ; ต้นทางไม่มี formal reviews หรือ inline review comments ณ เวลาที่ API ส่งกลับ
- ไฟล์แนบ GitHub 18/18 ไฟล์ พร้อม URL ต้นทางและ checksum
- labels 13 รายการ และตรวจ releases/ไฟล์ release assets ซึ่งมีจำนวน 0
- Git mirror ของต้นทาง: 7 branches, 1 tag และ PR refs 159 รายการ โดยปิด URL สำหรับ push ของชุดเก็บ

การเก็บทั้งหมดใช้การอ่านต้นทางและเขียนสำเนาในเครื่อง ไม่สร้างหรือแก้ Issue/PR ในโครงการต้นทาง ชุดนี้ไม่ใช่การย้าย collaborators, permissions, GitHub secrets หรือการตั้งค่าฝั่งบริการทั้งหมด

## ข้อมูลที่ไม่ตรงกันและข้อจำกัด

1. **ข้อมูลสัญญาอนุญาตไม่ตรงกัน:** [ไฟล์ LICENSE](../../LICENSE) เป็น Apache 2.0 แต่ [package.json](../../package.json) ระบุ ISC เป็นข้อมูลที่สืบทอดจากต้นทาง ต้องยืนยันเจตนากับผู้ดูแลต้นทางก่อนเปลี่ยนข้อความสัญญาอนุญาตเอง
2. **ยังไม่พิสูจน์การกู้คืนจนเปิดระบบได้:** ฐานจริงหยุดก่อนสำรองด้วย exit code 137 จึงอาจต้องทำ crash recovery เมื่อเปิดสำเนา การอ่าน tar/checksum ไม่ยืนยันว่า MySQL และแอปจะเปิดทำงานครบ
3. **ชุดเก็บเป็น snapshot:** source roots เก็บคนละเวลา ภายหลังพบ production log โตและ Codex refs เปลี่ยน ข้อมูลเหล่านี้เปลี่ยนหลังเก็บ ไม่ใช่ไฟล์ที่หายจากชุดเก็บ ณ เวลาที่บันทึก
4. **ของที่สร้างใหม่ได้ไม่ได้คัดลอก:** node_modules ใช้ package-lock.json เพื่อติดตั้งใหม่ ไม่เก็บ global caches, Windows installation หรือ Docker Desktop VM ทั้งก้อน
5. **ยังไม่มีเว็บสาธิตออนไลน์หรือคลิปแนะนำ:** ข้อมูลจริงและรหัสตั้งค่าไม่ได้อยู่ใน Portfolio ใช้ข้อมูลจำลองเมื่อเตรียมตัวอย่างเผยแพร่

รอบนี้ไม่ได้รันชุดทดสอบแอปทั้งหมด, authenticated HTTP API, การลงชื่อเข้าใช้จริง, การกู้คืน MySQL/SQL, migration หรือ Scheduled Tasks จากสำเนา จึงสรุปได้ว่าข้อมูลที่ตรวจตามบัญชีครบและอ่านได้ แต่ยังไม่รับรองว่ากู้คืนระบบแล้วใช้งานได้ทุกเส้นทาง
